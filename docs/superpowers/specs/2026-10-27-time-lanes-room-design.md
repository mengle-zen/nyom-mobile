# 방 화면을 시간 띠로 — 설계

2026-10-27 · 상태: 사용자 검토 대기

## 왜

친구 사용자 피드백(2026-10-27 대화):

- 아침·점심·저녁·간식으로 나누는 게 별로다. 타임스탬프처럼 찍은 시각을 바로 쓰고, 앨범처럼 보였으면.
- 누구랑 비교하기보다 각자의 사진첩을 들여다보는 느낌.
- 방(그룹)과 올림 알림은 유지.
- 방에 들어가면 누르지 않아도 멤버별 칸으로 나뉜 사진첩이 보이게. 다섯 명 이상은 보기 불편하니 인원을 제한.

시안(https://claude.ai/artifact/7yHLxsGec8skYuTcAf3PSh) 세 안 중 **C 시간 띠**를 골랐다.
C는 비교 느낌이 가장 강한 안이라, 숫자 배지·「아직이에요」 같은 비교 장치는 넣지 않는다.

## 결정 요약

| 항목 | 결정 |
| --- | --- |
| 방 화면 | 끼니 보드를 시간 띠(`TimeLanes`)로 교체. 끼니 보드는 남기지 않는다 |
| 시간축 | 빈 구간 접기 — 1시간 넘게 빈 시간은 접힌 줄 하나 |
| 겹침 | 같은 띠에서 겹치면 아래로 밀어냄. 순서는 정확, 간격은 대략 |
| 끼니 칸 | 앱 어디에도 끼니 이름을 보여 주지 않는다. 새 기록은 `meal_slot = null` |
| 끼니 태그 | 남긴다. 페이지를 나누지 않고 사진 위 작은 글자로만 |
| 최대 인원 | 4명. 서버 정원을 8 → 4로(웹 저장소 마이그레이션) |
| 올림 알림 | 문구는 그대로. 딥링크는 날짜만 쓰고 그날 가장 최근 사진으로 스크롤 |
| 태그 지우기 | 편집에서 가능. 편집 RPC가 빈 태그('')를 "끼니·태그 둘 다 비우기"로 받는다 |
| 리액션 | 띠에서는 빼고 상세에서만 |

## ① 방 화면 구성

위에서부터:

1. **헤더** — 그대로(← · 날짜 `‹ 오늘 ›` · 내 아바타). 끼니 칩 줄과 「n/m 올림」 배지는 없앤다.
2. **멤버 머리줄** — 띠마다 아바타 + 이름. 세로 스크롤해도 위에 붙어 있다.
   순서는 나 → 나머지는 방에 들어온 순서(멤버 조회가 이미 `joined_at` 순이라 나만 앞으로 뺀다).
3. **시간 띠 본문** — 세로 스크롤. 왼쪽 좁은 칸에 시각 눈금, 멤버마다 띠 하나.
   - 사진은 띠 폭 정사각형. 오른쪽 아래에 오렌지색 시각 각인(`12:31`), 태그가 있으면 왼쪽 위에 작은 글자.
   - 오늘이면 「지금」 선(가는 오렌지 선).
4. **촬영 버튼** — 그대로.

조작:

- 세로 스크롤 = 시간, 좌우 밀기 = 날짜. 세로 스와이프 끼니 넘기기와 화면 끝 30% 탭은 없앤다.
  날짜 팬 제스처는 가로로 확실히 움직일 때만 잡고 세로 스크롤에 양보한다.
- 사진을 누르면 상세 캐러셀(`PostDetail`). 넘기는 범위는 **그 사람의 그날 사진 전체**(시각순), 누른 사진부터 연다.
- 리액션은 상세에서만 단다(4명이면 띠 폭이 약 60pt라 칩이 들어가지 않는다).

처음 열 때 위치:

- 오늘: 가장 최근 사진이 보이게. 지난날: 맨 위부터.
- 알림으로 들어오면 그날을 열고 가장 최근 사진 쪽으로.

빈 상태:

- 안 올린 사람의 띠는 그냥 비어 있다(문구 없음).
- 그날 아무도 안 올렸으면 지금의 빈 화면(`NoRecordEmpty`)을 그대로 쓴다.
- 하루 경계는 지금처럼 자정(로컬 날짜).

이미 5명 이상인 방: 띠 폭을 4명 기준으로 고정하고 띠 영역을 가로로 밀어 본다(시각 눈금 칸은 고정).

## ② 배치 규칙

순수 함수 하나가 계산하고 화면은 그 결과를 그린다.

```ts
timeLanesLayout(input: {
  lanes: { userId: string; posts: { id: string; at: string }[] }[]  // 띠 순서대로, at = recorded_at
  photo: number          // 사진 한 변(pt) = 띠 폭
  now: Date | null       // 오늘이면 지금, 지난날이면 null
}): {
  height: number
  items: { postId: string; lane: number; y: number }[]
  marks: ({ kind: 'tick'; y: number; label: string } | { kind: 'fold'; y: number; from: string; to: string })[]
  nowY: number | null
}
```

규칙:

- **축척** — 사진이 있는 구간에서 30분 = 사진 한 변. 같은 사람 사진이 30분 넘게 떨어지면 겹치지 않는다.
- **구간** — 사진 한 장은 그 시각부터 30분을 차지한다. 모든 띠의 자리를 합쳐 구간을 만들고,
  구간 사이가 **1시간 초과**로 비면 24pt 접힌 줄(`13:00 ─ 15:30`)로 바꾼다. 1시간 이하는 그대로 그린다.
- **밀어내기** — 같은 띠에서 앞 사진 아래 끝 + 4pt보다 위에 오면 그 자리로 민다.
  구간의 높이는 선형 높이와 "그 구간에서 가장 아래로 밀린 사진의 끝" 중 큰 값이다. 다음 구간은 그 아래에서 시작한다.
- **눈금** — 구간 시작에 첫 사진 시각의 정시(`12:00`), 구간 안에서는 정시마다.
- **지금 선** — `now`가 구간 안이면 그 자리, 마지막 구간보다 1시간 넘게 뒤면 접힌 줄 다음 맨 아래, 그 사이면 마지막 구간 끝에서 선형으로.
- 사진에 각인된 시각은 늘 정확하다(위치가 밀려도).

## ③ 올리기 · 편집 · 다른 화면

올리기(`ShotEditor`):

- 끼니 알약을 없애고 한 줄: `시각 21 : 10` · `＋ 태그`.
  - 시각은 찍은 시각이 기본이고 `TimeField`(시·분 두 칸)로 고친다. 최대는 지금. `TimeField`에 어두운 화면 모양(`onDark`)을 더한다.
  - 태그는 `MealSlotChips`에서 기본 끼니 네 칩을 뺀 태그 입력만(그 자리 입력 + 최근 태그 칩). 컴포넌트 이름도 `MealTagPicker`로 바꾼다.
- 저장: `meal_slot = null`, 태그는 붙였을 때만 `meal_tag`.
- 보낸 뒤 그날 보드를 열고 방금 올린 사진으로 스크롤. 되돌리기는 시각·태그를 들고 돌아온다.

기록 편집(`PostEditSheet`):

- 끼니 네 칩을 빼고 태그 · 섭취 시각 · 메모 · 공유 그룹.
- 태그 지우기 = 편집 RPC에 `p_meal_tag = ''`. 예전 기록의 `meal_slot` 값은 화면에 안 보일 뿐 건드리지 않는다(태그를 붙이거나 지울 때만 RPC 규칙대로 바뀐다).

다른 화면:

- 프로필 그리드·달력·상세의 「점심 · 12:31」 → 「12:31」, 태그가 있으면 「야식 · 23:40」.
- 그룹: 정원 4명은 서버가 막는다. 앱은 기존 `GROUP_FULL` 처리(「이 그룹은 정원이 찼어요」)를 그대로 쓰고,
  방장 화면의 가입 요청 수락 버튼은 4명이면 미리 끈다.
- 알림 딥링크: `slot`·`tag`는 무시하고 날짜만.

지우는 것: `widgets/slot-chips`, `widgets/slot-board`, `entities/post/slot-progress`(페이지 목록·`pageIndex`),
`boardPages`·페이지 키, `defaultSlotForHour`, 관련 테스트. 화면 끝 탭 판정 `edgeZone`은
웹과 같은 파일(`features/board-nav/axis.ts`)이라 지우지 않고 호출만 없앤다.
`buildSlotBoard`의 "멤버별 그날 기록" 부분은 띠 데이터 만들기로 바꿔 남긴다.

## ⑤ 확인과 출시 순서

테스트(vitest):

- `timeLanesLayout`: 같은 띠 겹침 없음, 띠 안 순서 = 시각 순서, 1시간 초과 빈 구간만 접힘,
  밀린 뒤 다음 구간 시작 위치, 0장·1장, 지금 선 세 경우.
- 띠 순서(나 → 들어온 순), 그 사람의 그날 사진 목록, 표시 라벨(시각 · 태그).

DB(로컬 Supabase): 빈 태그로 지우기, 태그 바꾸기, 5인자 예전 호출, 5번째 가입 `GROUP_FULL`.

화면(시뮬레이터): 로컬 서버에 예시 방(4명, 가까운 시각 사진·긴 빈 구간·태그·어제 기록)으로
스크롤·날짜 넘기기·상세·올리기·편집·정원 확인. 운영에서는 테스트 계정 「E2E 전용」 방에서 올리고 바로 지운다.
Maestro `03-board`·`05-upload`를 새 화면에 맞춘다.

순서:

1. 웹 마이그레이션 → 로컬 검증 → **운영 적용은 사용자 확인 후**
2. 모바일 구현 → `main`
3. 빌드 13 TestFlight (시각 직접 입력 `641e20d` 포함)

빌드 12 이하는 끼니 칸이 빈 새 기록을 보드 어느 칸에도 못 보여 준다 — 친구들이 13으로 올려야 서로 보인다.
