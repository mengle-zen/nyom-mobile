# 보드 재설계 — 시간 밴드 스트림과 자유 끼니 태그

- 날짜: 2026-08-31
- 상태: 승인 대기 (사용자 리뷰 중)
- 저장소: `nyom-app` (앱) + `nyom` (마이그레이션)
- 참고: 셋로그(Setlog)의 시간 리듬, `nyom/docs/UX_FINDINGS.md` B항

## 목적

하루를 **고정 4끼니 칸**으로 나누던 보드를 **시간 밴드 스트림**으로 바꾼다.
끼니 이름은 칸이 아니라 **사용자가 쓰는 태그**가 된다.

바뀌는 이유는 두 가지다.

1. **칸이 부족하다.** 점심과 저녁 사이에 간식을 3번 먹으면 지금 모델은 그 3개를
   「점심」 칸 하나에 대표 1장 + `+2`로 묶는다. 3번 먹은 사실이 화면에서 사라진다.
   앞으로 끼니를 늘릴 가능성을 생각하면 칸을 미리 정해두는 구조 자체가 병목이다.
2. **칸이 제스처를 망가뜨렸다.** 세로=끼니 / 가로=날짜 두 축을 직접 판정하느라
   사진 탭이 끼니를 넘기는 버그가 났다(UX_FINDINGS B항). 칸이 없어지면 축이 하나가 된다.

## 결정 사항

브레인스토밍에서 확정된 것. 각 항목의 대안과 탈락 이유는 「검토했지만 택하지 않은 것」에 있다.

1. **보드는 통합 시간축 스트림이다.** 그룹 하루의 모든 기록이 한 스트림에 시각순으로 섞인다.
   멤버별 타일 격자를 버린다. 사진이 화면 폭을 다 쓴다.
2. **스트림은 2시간 밴드로 묶인다.** 밴드는 `recorded_at`에서 파생한다 — 테이블도 마이그레이션도 없다.
   기록이 없는 밴드는 나타나지 않는다. 밴드 폭은 상수 `BAND_HOURS = 2`.
3. **끼니는 자유 문자열 태그다.** 「아침」「점심」「간식」「해장」 등 사용자가 쓴 그대로 저장한다.
   고정 4값 제약을 제거한다.
4. **태그는 자동으로 채워지고, 탭하면 고친다.** 섭취 시각으로 기본값이 들어가 있어
   기본 경로는 탭 수 증가가 없다. 칩을 탭하면 최근 태그 칩 + 자유 입력이 열린다.
5. **태그는 1개, 최대 8자.** 복수 태그는 범위 밖.
6. **통계·집계는 태그가 아니라 시각대에서 파생한다.** 자유 문자열은 집계 키로 쓸 수 없다.
7. **상단에 멤버 아바타 줄을 둔다.** 각 멤버의 그날 기록 수를 배지로, 안 올린 사람은 점선 아바타로.
8. **웹앱(`nyom` 프론트)은 따라가지 않는다.** 이 변경은 모바일 단독이다.

## 데이터 모델

`posts.meal_slot`은 이미 `text` 컬럼이라(enum 아님) 변경이 작다.

| 항목 | 지금 | 바뀐 뒤 |
| --- | --- | --- |
| `posts.meal_slot` | `text` + `check in ('breakfast','lunch','dinner','late_snack')` | `text`, 제약 없음. 값은 사용자가 보는 한국어 문자열 |
| 정규화 | 없음 | `trim`, 연속 공백 1칸, 8자 절단, 빈 문자열 → `null` |
| 스트림 정렬 | `meal_slot` 순서 | `recorded_at` 오름차순, 동시각이면 `created_at` |
| 밴드 | 없음 (칸이 곧 밴드) | `floor(hour / 2)` 파생. 저장하지 않음 |
| 집계 키 | `meal_slot` | `recorded_at`의 시각대 |

컬럼명 `meal_slot`은 **바꾸지 않는다.** 의미는 「끼니 태그」로 바뀌지만, 이름을 바꾸면
마이그레이션·타입·RPC 시그니처가 전부 흔들린다. 주석으로 의미 변경을 남긴다.

### 세 가지 시간 구간을 혼동하지 말 것

이 스펙에는 시간을 나누는 규칙이 셋 있고, **서로 경계가 다르다.** 일부러 다르다.

| 규칙 | 용도 | 경계 | 화면에 이름이 나오나 |
| --- | --- | --- | --- |
| **밴드** (2시간) | 스트림 묶음 | `floor(hour/2)` | 아니오 — 헤더는 「12–14시」처럼 **시각 범위만** |
| **태그 자동값** | 업로드 기본 태그 | `defaultSlotForHour` (야식 0–5, 아침 5–11, 점심 11–16, 저녁 16–21, 야식 21–24) | 예 — 태그 칩에 「점심」 |
| **시각대** (6구간) | 통계 집계 | 아래 표 | 돌아보기 통계 화면에서만 |

**밴드 헤더에 이름을 붙이지 않는 이유가 여기 있다.** 붙이면 15:20 기록이
태그는 「점심」인데 헤더는 「오후」가 되어 사용자에게 모순으로 읽힌다.
헤더를 시각 범위만으로 두면 그 충돌이 원천적으로 생기지 않는다.

### 시각대 (통계 집계용, 태그와 무관)

돌아보기·프로필 통계는 이 구간으로 계산한다.

| 시각대 | 범위 |
| --- | --- |
| 새벽 | 00–05 |
| 아침 | 05–11 |
| 점심 | 11–14 |
| 오후 | 14–17 |
| 저녁 | 17–21 |
| 밤 | 21–24 |

## 화면 설계

### 보드

```
┌──────────────────────────────────┐
│ 우리 점심방            ‹ 8/31 토 › │  ← 날짜: 헤더 화살표 + 가로 스와이프
│ (효)⁴ (지)² [수] (민)¹    3/4명    │  ← 멤버 아바타 줄. [수]는 점선 = 미기록
├──────────────────────────────────┤
│ ─── 08–10시 ─────────────────── │  ← 밴드 헤더(시각 범위만). 빈 밴드는 없음
│ (효) 효린  08:10  [아침]           │
│ ┌────────────────────────────┐   │
│ │          사진 (정사각)        │   │  ← 폭을 다 씀
│ └────────────────────────────┘   │
│ 출근길 커피                        │
│ 🤤 2  ＋                          │
│                                  │
│ ─── 12–14시 ─────────────────── │
│ (효) 효린  12:40  [점심]  …        │
│ (지) 지훈  13:05  [점심]  …        │  ← 12:40과 13:05가 같은 밴드에 모인다
│ (민) 민지  13:10  [점심]  …        │
└──────────────────────────────────┘
   세로 스크롤 = 그 날의 시각순
```

- **가로 스와이프 = 날짜**(최근 2주), **세로 스크롤 = 그 날의 시각순.**
  두 축이 동시에 쓰이지 않으므로 직접 만든 축 판정이 필요 없다. RN 중첩 스크롤에 맡긴다.
- 같은 사람이 연속으로 올렸어도 **카드를 합치지 않는다.** 간식 3번이 3장으로 보이는 게 이 설계의 요점이다.
- 카드 = 아바타·닉네임·시각·태그 칩 / 사진(정사각) / 메모 / 리액션 줄.
- 사진 탭 = 상세 보기(`widgets/post-detail` 재사용). 축 충돌이 없어 `data-ctl` 류의 회피가 불필요하다.
- 밴드 헤더 문구는 `시작–끝시`(예: 「12–14시」). **이름을 붙이지 않는다** — 이유는
  「세 가지 시간 구간」 절에 있다. 사용자 입력에 영향받지 않고, 태그와 모순될 일도 없다.

### 빈 상태

| 상황 | 화면 |
| --- | --- |
| 그날 아무도 안 올림 | 🍽 「이 날은 아무도 안 올렸어요」 + 「지금 올리기」. 아바타 줄은 전원 점선, `0/4명` |
| 그룹에 아무도 없음(나 혼자) | 기존 문구 유지. 스펙 4에서 다시 다룸 |

### 태그 입력 (업로드 · 사후 편집 공용)

```
[ 사진 ]
15:20  [간식 ⌄]        ← 섭취 시각으로 자동 채워짐. 그대로 게시 가능
   ↓ 칩을 탭하면
   ┌─────────────────────────────┐
   │ [간식] [해장] [야식] [브런치]  │  ← 내 최근 태그. 원탭 재사용
   │ ┌─────────────────────────┐ │
   │ │ 직접 입력…                │ │  ← 8자 제한
   │ └─────────────────────────┘ │
   └─────────────────────────────┘
한 줄 메모 (선택)
```

- 자동 채움은 `defaultSlotForHour(hour)`가 반환하는 한국어 라벨.
- **최근 태그는 내 기록에서 자동 집계한다.** 관리 화면은 만들지 않는다.
  집계 규칙: 내 최근 60일 게시물의 `meal_slot`을 빈도 내림차순, 동빈도는 최신순, 상위 6개.
  기록이 없는 신규 사용자에게는 씨앗 목록 `아침·점심·저녁·야식·간식`을 보여준다.
- 사후 편집도 같은 컴포넌트를 쓴다. 지금은 편집에 끼니 칩이 있으니 UI가 교체되는 것이다.

## 백엔드 변경

마이그레이션은 **`nyom` 저장소**에 쓴다(`supabase/migrations/`). 백엔드 소유권 규칙은 그대로 따른다.

### `<ts>_meal_tag_freeform.sql`

1. **정규화 함수 신설**

```sql
create or replace function public.normalize_meal_tag(p_input text)
returns text
language sql
immutable
as $$
  select nullif(left(regexp_replace(btrim(p_input), '\s+', ' ', 'g'), 8), '')
$$;
```

앱에도 같은 규칙의 `normalizeMealTag()`를 두고, 두 구현이 어긋나지 않도록 테스트로 고정한다.

2. **제약 제거와 기존 값 변환**

```sql
alter table public.posts drop constraint if exists posts_meal_slot_check;

update public.posts set meal_slot = case meal_slot
  when 'breakfast'  then '아침'
  when 'lunch'      then '점심'
  when 'dinner'     then '저녁'
  when 'late_snack' then '야식'
  else meal_slot
end;
```

**되돌릴 수 없다.** 변환 후에는 원래 키를 복원할 수 없다(「아침」이 `breakfast`였는지
사용자가 직접 쓴 것인지 구분 불가). 마이그레이션 파일 주석에 명시한다.

3. **`update_post_batch` (5-arg) 수정**

`p_meal_slot not in ('breakfast', …)` 검사를 제거하고
`v_slot := coalesce(public.normalize_meal_tag(p_meal_slot), v_rep.meal_slot)`로 바꾼다.
`null` = 「태그 변경 없음」이라는 기존 의미는 유지한다.

4. **게시 경로에도 정규화 적용**

앱이 직접 `insert`하는 경로가 있으므로 `posts`에 `before insert or update` 트리거를 걸어
`new.meal_slot := public.normalize_meal_tag(new.meal_slot)`를 강제한다.
앱만 믿으면 RPC를 우회한 값이 그대로 들어온다.

5. **`notify_group_on_post` 수정**

`case s.meal_slot when 'breakfast' then '아침' … end`로 한국어를 만들던 부분을 삭제하고
`s.meal_slot`을 그대로 쓴다. `group by`의 `slot_ko`도 정리한다.

6. **딥링크 파라미터 교체**

`'&slot=' || rep.meal_slot` → `'&post=' || rep.post_id`.
슬롯 인덱스로 보드 위치를 잡던 방식이 스트림에서는 의미가 없다.

### 보안 고려

태그가 자유 입력이 되면 **사용자가 쓴 문자열이 다른 멤버의 푸시 알림 본문에 실린다**
(`notify_group_on_post`가 「효린님이 점심을 남겼어요」를 만든다).
방어선은 8자 절단 + `trim`이고, 그것을 **DB 트리거에 두는 것**이 이 스펙의 요구사항이다.
알림 본문은 평문으로만 렌더되므로(웹 푸시/APNs 모두) 마크업 주입 위험은 없다.

| `normalizeMealTag` | 공백만 → `null` / 8자 초과 절단 / 연속 공백 1칸 / 앞뒤 공백 / 이모지 포함(자소 분리 없이 절단) |
| `timeBucketOf` | 6개 구간 경계 전부 |
| `recentTags` | 빈도순 / 동빈도 최신순 / 상위 6개 절단 / 기록 없으면 씨앗 목록 |
| `defaultSlotForHour` | 기존 새벽 0~4시 케이스 유지(반환값이 문자열) |
| `deeplinkTarget` | `post` 있음 / 없음 / 존재하지 않는 id → 오늘로 폴백 |

### DB와 앱 정규화 일치

`normalizeMealTag`의 테스트 케이스 표를 SQL 쪽에서도 같은 입력으로 검증한다.
두 구현이 어긋나면 앱에서 8자로 보이던 태그가 DB에서 다른 값이 되어 조용히 갈라진다.

## 마이그레이션 순서

앱과 DB를 동시에 배포할 수 없으므로 순서가 중요하다.

1. **DB 먼저** — 제약 제거는 기존 앱을 깨지 않는다(기존 앱은 4개 값만 보내니 여전히 유효).
   값 변환(`breakfast`→`아침`)은 **기존 앱을 깨뜨린다** — 구버전 앱의 `MealSlotKey` 유니온에
   「아침」이 없어 끼니 라벨이 빈 문자열로 표시된다. 크래시는 아니고 표시 누락이다.
2. **앱 배포** — 스토어 심사 지연이 있으므로 1과 2 사이에 표시 누락 구간이 생긴다.
   지금은 실사용자가 없어 무해하다. 사용자가 생긴 뒤에는 이 순서를 쓸 수 없다.
3. 웹앱은 이 시점에 끼니 표시가 깨진다. 안 쓰기로 했으므로 방치한다(스펙 3에서 배포 내림).

롤백: 제약을 되돌릴 수는 있으나 **값 변환은 되돌릴 수 없다.** 롤백 계획은
「제약을 다시 걸지 않는다」이고, 문제가 생기면 앱을 이전 버전으로 되돌린다.

## 검토했지만 택하지 않은 것

기록해 둔다 — 나중에 같은 논의를 반복하지 않기 위해.

| 안 | 왜 택하지 않았나 |
| --- | --- |
| **슬롯 5개로 고정 확장**(간식 추가) | 「간식 3번」을 못 담는다. 칸을 미리 정하는 구조의 한계가 그대로 남는다 |
| **멤버 레인**(세로=멤버, 가로=시간) | 미기록이 빈 레인으로 남는 장점이 있지만 사진이 33px급으로 작아진다. 음식 사진 앱에서 치명적 |
| **끼니 라벨 폐기** | 시간축이면 「08:10」에 「아침」은 중복이라는 판단은 성립하지만, 사용자가 태그를 직접 쓰고 싶다는 요구가 명확했다 |
| **자동 추론만, 수정 불가** | 새벽 3시 라면을 「야식」으로 고칠 방법이 없다. UX_FINDINGS C항이 정확히 그 문제였다 |
| **밴드 1시간** | 12:40과 13:05가 다른 밴드로 갈라진다. 밴드의 존재 이유가 「같은 끼니를 나란히」인데 그걸 못 해준다. 다만 `BAND_HOURS` 상수 하나라 나중에 바꿀 수 있다 |
| **밴드를 참조 테이블로** | 시계가 경계를 정하면 테이블이 필요 없다. 「누가 경계를 정하나」 문제도 같이 사라진다 |
| **태그를 집계 키로** | 「간식」과 「간식 」이 다른 값이 되어 통계가 못 믿을 값이 된다. 그래서 시각대 파생으로 분리했다 |

## 열린 질문

이 스펙에서 답하지 않는다. 후속 스펙에서 다룬다.

1. **스트림이 길어질 때** — 4명이 각각 3번씩 먹으면 카드 12장이다. 페이지네이션이 필요한
   시점인지, 밴드 접기가 필요한지는 실사용 후 판단한다.
2. **멤버 아바타 줄의 압박** — 「안 올린 사람 점선」이 PRODUCT_PLAN 12절 판단 기준 3
   (식단 관리 압박을 만들지 않는가)에 걸리는지는 써보고 판단한다.
3. **`meal_slot` 컬럼명** — 의미가 「태그」로 바뀌었는데 이름은 「슬롯」이다. 언젠가 정리할 부채.
